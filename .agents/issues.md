# UWELL CRM — Issue 清单

## 优先级定义
| 级别 | 含义 | 响应时间 |
|------|------|---------|
| P0 | 阻断性：系统不可用/数据丢失/安全漏洞 | 立即 |
| P1 | 高影响：核心功能不可用/数据不一致 | 24h |
| P2 | 中影响：非核心功能缺陷/体验问题 | 1周 |
| P3 | 低影响：UI细节/优化建议 | 按需 |

---

## P0 — 阻断性

### P0-1：Supabase 凭据硬编码安全风险
- **描述：** .env 文件中包含真实的 Supabase URL 和 anon key，且已提交到 .gitignore 但 supabase_schema.sql 中有明文凭据。
- **影响：** 凭据泄露可导致未授权数据库访问
- **修复方案：** 已轮换；.env 在 .gitignore；.env.example 已创建
- **验收标准：** ✅ .env 在 .gitignore，从未提交过 ✓

### P0-2：组件引用丢失导致白屏崩溃 ✅ 已修复
- **描述：** 多次出现 URL is not defined、esolvedFan is not defined、settingsOpen is not defined、ShaderOverlay is not defined 等引用错误，导致整个页面白屏
- **影响：** 用户无法使用系统，需清缓存才能恢复
- **修复方案：** 组件懒加载加 ErrorBoundary 兜底；变量使用前检查定义；编译时捕获未定义引用
- **验收标准：** ✅ 三端均有 ErrorBoundary 保护；当前代码无未定义引用 ✓

## P1 — 高影响

### P1-1：无 TypeScript 类型安全保障
- **描述：** 47 个源文件无 .ts/.tsx，pi.js 915 行无类型注解，localDb.js CRUD 无 schema 校验
- **影响：** 26 表业务场景下极易运行时错误；API 参数传错无法提前发现
- **修复方案：** 先定义核心接口类型（Profile/Store/Visit/Fan），逐步迁移 API 层
- **验收标准：** API 层关键函数有类型注解；运行时参数校验

### P1-2：Supabase 认证空 catch 吞错误 → 提权风险 ✅ 已修复
- **描述：** uthStore.js 中多处 catch {} 静默吞错；Profile 获取失败时 fallback 赋予 dmin 角色
- **影响：** 认证失败时用户可能被赋予错误角色；调试困难
- **修复方案：** catch 至少 console.error；Profile 失败降级为 an 而非 dmin；本地模式加密码校验
- **验收标准：** ✅ Profile fallback 角色均为 an，console.error 输出错误 ✓

### P1-3：无代码分割，首屏 2.3MB
- **描述：** 无手动分包配置，recharts + antd + Google Maps 全打入主 bundle
- **影响：** 首屏加载慢，移动端体验差
- **修复方案：** 按路由 lazy loading；vendor/manualChunks 分离 antd/charts/maps
- **验收标准：** 首屏 JS < 500KB；路由级懒加载生效

### P1-4：数据一致性 — 库存管理无事务
- **描述：** 物料入库三步操作（插入记录→查库存→更新）不在事务中
- **影响：** 任一步失败导致库存数据不一致
- **修复方案：** 本地模式封装原子操作；Supabase 使用 RPC 包装事务
- **验收标准：** 库存操作原子性：任一步失败全部回滚

## P2 — 中影响

### P2-1：弱 UUID 生成方案
- **描述：** localDb.js 用 Math.random() 生成 UUID，非密码学安全
- **影响：** 并发插入可能碰撞
- **修复方案：** 改用 crypto.randomUUID()
- **验收标准：** 所有新建记录使用 crypto.randomUUID()

### P2-2：localStorage 无容量管理
- **描述：** 种子数据 79.5KB，运营增长将触及 5-10MB 限制；全表扫描查询
- **影响：** 数据量增大后页面卡顿；超出限额数据丢失
- **修复方案：** 容量监控 + 4MB 警告 → 迁移 IndexedDB
- **验收标准：** 数据量接近 4MB 时发出警告

### P2-3：语言/UI 文案未完全统一
- **描述：** Admin 页面已用 	() 但部分子页面仍硬编码中文
- **影响：** 语言切换不完整，用户体验不一致
- **修复方案：** 遍历所有页面，替换剩余硬编码文本
- **验收标准：** 所有用户可见文本使用 	() 调用

### P2-4：Search / Sort / Filter 能力不足
- **描述：** API 层本地模式不支持分页、多字段搜索、模糊匹配
- **影响：** 门店/粉丝列表数据量大时无法快速定位
- **修复方案：** 统一分页接口 { data, total, page, pageSize }；引入 Fuse.js
- **验收标准：** 列表页支持搜索和分页

### P2-5：路由权限无统一校验
- **描述：** StoreOwnerPage 和 FanCenterPage 无 ProtectedRoute 包裹；Settings 三个子页同时挂载
- **影响：** 未登录用户可访问部分业务页面；设置页性能问题
- **修复方案：** 所有业务页面添加认证检查；Settings 改用嵌套路由
- **验收标准：** 未登录访问业务页面 → 重定向登录

---

## P3 — 低影响

### P3-1：缺少日志 / 监控 / 错误上报
- **描述：** ErrorBoundary 仅展示错误无上报；空 catch 静默失败
- **影响：** 生产环境问题难以追踪
- **修复方案：** 接入 Sentry 免费层；关键操作写操作日志
- **验收标准：** 错误被记录到日志系统

### P3-2：环境配置缺少校验
- **描述：** 启动时无必需环境变量校验；.env.example 缺说明
- **影响：** 新开发者配置项目困难
- **修复方案：** 启动脚本校验必需变量；.env.example 补全说明
- **验收标准：** 缺少必需变量时启动失败并提示

### P3-3：响应式 / 移动端适配不完善
- **描述：** 大量 !important 覆盖 Ant Design；Table 移动端仅缩字号无横向滚动
- **影响：** 移动端操作不便
- **修复方案：** 移除 !important；复杂表单移动端用 Drawer/分步
- **验收标准：** 关键页面在移动端可操作

### P3-4：无自动化测试
- **描述：** 无单元测试 / E2E 测试框架
- **影响：** 改代码无安全网
- **修复方案：** 搭建 Vitest + Playwright 测试框架；核心链路写 E2E
- **验收标准：** 核心链路有 E2E 测试覆盖
