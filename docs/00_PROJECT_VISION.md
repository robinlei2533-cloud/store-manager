# UWELL CRM Project Vision

## One Sentence

UWELL CRM is a trial-operations platform that connects fans, stores, field teams, managers, and admins into one operating system for consumer growth, store execution, marketing campaigns, materials, visits, data, and ROI.

## Product Name

Working name: **UWELL Operating System**

Current project name: **UWELL CRM**

## Final Direction

The long-term product is not only a CRM. It should become:

- CRM: fans, stores, contacts, complaints, records.
- DMS: stores, regions, warehouses, materials, field visits.
- Marketing Platform: campaigns, engagement tasks, rewards, community, scan codes.
- Operations Console: reviews, risk, audit, region access, reporting.

## Core Users

| User | Main Need |
|---|---|
| Fan | Earn points, join activities, scan UWELL products, redeem rewards, find stores |
| Store owner | Verify fans, join campaigns, submit activities, manage store profile and photos |
| Field rep | Visit new/repeat stores, collect display data, submit rating evidence |
| Manager | Review regional stores, visits, materials, campaigns, risks |
| Admin | Manage all rules, accounts, reviews, regions, rewards, scan codes, audit |

## Non-negotiable Direction

- This is a three-portal product, not one mixed website.
- Fan, store, and backend experiences must stay separate.
- Existing business functions are not discarded during redesign.
- UI upgrades must improve layout, navigation, clarity, and product experience without removing confirmed functions.
- All future development must follow the documented rules before coding.

## Current Stage

Current stage: local trial MVP / pre-public-launch refinement.

Approximate state:

- Trial MVP: about 75%.
- Public production readiness: about 45%.

## Product Success Criteria

- Fans understand what to do within seconds.
- Stores can complete high-frequency tasks quickly.
- Field reps submit useful visit and rating data.
- Managers and admins can see pending work and operational health clearly.
- Rules, permissions, database, and UI stay consistent across portals.
